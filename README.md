# 漫游 · City Wander

给城市生活绕一点路：在杭州，按时间和沿途偏好生成驾车/步行环线，预览之后交给手机高德。

## 启动

需要 Node.js 22.12+（当前用 Node 26 验证）。

```sh
npm install
cp .env.example .env
npm run dev
```

如果 `.env` 已存在，直接编辑，不要覆盖。打开 http://localhost:5173 。前端默认 5173，API 默认 3001。没有 Key 也可以操作演示，示意路线不会提供导航入口。

## 申请高德 Key

1. 登录 [高德开放平台控制台](https://console.amap.com/)，注册开发者，完成个人认证。
2. 在“应用管理 → 我的应用”创建应用，可命名 `City Wander`。
3. 在应用下添加 Key，服务平台选 **Web 服务**，将 Key 填入 `.env` 的 `AMAP_WEB_KEY`。
4. 再添加一个 Key，服务平台选 **Web 端（JS API）**。将 Key 填入 `AMAP_JS_KEY`，该 Key 对应的安全密钥（securityJsCode）填入 `AMAP_SECURITY_JS_CODE`。
5. 保存后重启 `npm run dev`，刷新网页。搜索并选择真实起点，再点击生成；默认打开的仍是演示路线，只有成功调用高德后才出现真实路线。

```dotenv
AMAP_WEB_KEY=这里填Web服务类型的Key
AMAP_JS_KEY=这里填Web端JS_API类型的Key
AMAP_SECURITY_JS_CODE=这里填JS_Key对应的安全密钥
PORT=3001
```

`.env` 已被 `.gitignore` 排除。Web 服务 Key 只在后端使用，不添加 `VITE_` 前缀。开发版会把地图 JS Key 与 JS 安全密钥提供给浏览器；正式公开部署可改为高德推荐的安全代理。

官方步骤：[Web 服务 Key](https://lbs.amap.com/api/webservice/guide/create-project/get-key)、[Web 端 JS Key](https://lbs.amap.com/api/javascript-api-v2/prerequisites)。

2026-11-02 核对的个人认证月配额：基础 LBS 15 万次、搜索 5,000 次、地图定位 150 万次。官网注明符合条件的免费月配额权益期限为认证日起一年；具体权益、到期日期和限流以自己账号控制台为准。个人研究学习与公开商业运营的授权范围不同。来源：[配额及期限](https://lbs.amap.com/upgrade)、[计费与 QPS](https://lbs.amap.com/pages/base_service_price)、[使用条件](https://lbs.amap.com/faq/advisory/authorization/43168)。

## 已有功能

- 驾车/步行，15–180 分钟，默认回到起点。
- 随心、公园、滨水、高架软偏好；步行不能选择高架。
- 杭州地点搜索，浏览器定位并通过高德转换 WGS84 → GCJ-02。
- 地图选起点：局域网 HTTP 也能使用，地图坐标直接保留 GCJ-02；辅助估计位置需手动核对确认。
- 多个候选环线，按时长匹配排序；显示实际预计耗时和距离。
- 高德 JS 地图路线预览；地图不可用时明确显示无底图几何预览。
- 手机与桌面布局、路线切换、重新随机、设备本地收藏、复制清单。
- Android/iOS 高德多途经点链接，以及不丢途经点的逐段 Web 备选链接。

## 规划方式

根据出行方式与目标时间估算探索半径，采样三个方向，通过高德 POI 查询找公园/滨水地点等候选；比较不同途经点组合，再请求真实道路路径。驾车每条环线分成两次算路以兼容默认单途经点能力；步行分成三段。路径折线、道路、距离和耗时都解析自高德响应，不用直线补齐失败的路线。

第一轮最多用 3 次周边搜索 + 6 次驾车规划，或 3 次周边搜索 + 9 次步行规划。若最接近目标的实际耗时仍偏差超过 20%，最多增加一轮半径校准：再查 3 个方向并评估至多 2 组路线，进入 ±15% 即停止。合计硬上限驾车 16 次、步行 21 次高德调用，起点搜索另计；所有请求受 45 秒规划总期限约束。时长误差优先，同时参考近似重走比例；达不到目标时长会明确提示，不能保证恰好一小时。真实请求失败不会悄悄退回演示数据。

请求在进程内按至少 375ms 间隔启动，兼容个人 Key 的 3 QPS，排队上限 30。多实例部署需要共享限流器。

## 导航与车机边界

“高架优先”不是高德的独立算路参数：使用大路优先与路名启发式评分，不保证走上高架。滨水类别也是关键词偏好，不保证全程沿水。时间不包含游玩/停车。

手机高德接收起点、途经点和终点后重新算路，不能原样导入预览 polyline。当前公开 Web URI 只支持一个驾车途经点，因此本应用的浏览器备选方案按段打开。

高德车机版需要在手机高德内使用当前版本的手车互联/发送到车功能。官方说明证明了“发送位置”，没有保证所有车机支持整条多途经点环线。本项目没有第三方直推车机接口，也不会显示未经证实的发送成功。

完整参数和真机验证步骤见 [高德接入说明](docs/amap-integration.md)。

## 验证与部署

```sh
npm test
npm run build
npm start
```

`npm start` 在 http://127.0.0.1:3001 提供已构建的前端及 API。如需通过网络访问，按实际环境设置 `HOST`；手机 GPS 定位需要 HTTPS（localhost 除外）。开发时同一局域网可通过 Vite 输出的 Network 地址访问，但 HTTP 手机定位可能不可用，可先用搜索起点。

已验证 TypeScript、生产构建、规划/坐标转换/错误处理/导航链接的自动化测试，以及浏览器交互和手机布局。2026-11-02 已用真实 Key 在杭州城市阳台附近验证地点搜索、驾车和步行环线 API，并确认高德 JS 底图及路线正常绘制。时长校准后的实测样例：目标 60 分钟驾车返回 51.2 分钟/35.5 公里；目标 60 分钟滨水步行返回 52.1 分钟，途经亲水平台与江堤步道。样例只代表当时路况，不能保证任意起点均能命中目标。导航交接链接已检查；手机 App 唤起与车机版本兼容仍需真机验证。

## 手机无法获取当前位置

手机通过 `http://192.168...` 局域网地址访问时，不是浏览器认可的安全上下文，自动精确定位会被阻止；这与高德 Key 是否有效无关。`http://localhost` 是电脑本机的特殊例外，不能在手机上用 localhost 代替电脑地址。

当前可刷新页面，使用“地图选点”：拖动/缩放到实际位置，点击地图，再选择“从这里出发”。这不会调用浏览器定位权限，也不会把地图上的 GCJ-02 坐标再次转换。辅助“估计附近位置”可能来自 IP，精度未知时会明确提示，必须自己核对和点选；不会直接当成当前位置。

若需要手机自动定位，应将前端和 `/api` 部署到同一可信的 HTTPS 站点，再开启系统、浏览器和网站的位置权限。仅给局域网 HTTP 地址加 `https://` 无效；未经信任的自签名证书也不能当成已完成的手机定位方案。本地服务仍为 HTTP，本项目尚未公开部署或建立公网隧道。

HTTPS 下的权限拒绝、位置不可用、超时会分别提示；晚到的定位结果不会覆盖后来手动选择的起点。依据：[高德定位使用说明](https://lbs.amap.com/api/javascript-api-v2/guide/services/geolocation)、[浏览器安全上下文限制](https://developer.chrome.google.cn/blog/geolocation-on-secure-contexts-only?hl=en)。
